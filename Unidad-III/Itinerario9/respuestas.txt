1. ¿Qué es un Framework?

Un framework es un marco de trabajo que ofrece a quien lo utiliza, una serie de herramientas que le facilitan la realización de tareas.
Puede contener librerías de clases, documentación, ayuda, ejemplos, tutoriales, pero sobre todo “contiene experiencia sobre un dominio de problema específico”.
Un framework tiene como objetivos tres cosas: normalizar, estandarizar y reutilizar la experiencia.

2. ¿Qué son los frozen-spots en un Framework?

Los puntos congelados son aquellas partes del código provistas por el framework.

3. ¿Qué son los hot-spots en un Framework?

Los puntos calientes son las partes de código que coloca el programador e interactúan con el framework.

4. ¿Cómo se puede clasificar un Framework según su extensibilidad?

Un framework se puede también clasificar según su extensibilidad, puede ser utilizado como una caja blanca o caja negra.

5. ¿Qué es un Framework de Caja Blanca?

En los frameworks de caja blanca se crean de nuevas clases por herencia o composición.

6. ¿Qué es un Framework de Caja Negra?

En los frameworks de caja negra se producen instancias usando código o scripts de configuración.
Después de la configuración, una herramienta automática de instanciación crea las clases.

7. ¿Qué ventajas posee utilizar un Framework?

Entre las ventajas de utilizar frameworks podemos decir que el programador no necesita plantearse una estructura global de la aplicación, sino que el framework le proporciona un esqueleto que hay que “rellenar”.

8. ¿Qué problemas resuelve .NET Framework?

El .NET Framework provee la unificación de herramientas necesarias en run-time y compile-time para construir y ejecutar aplicaciones basadas en .NET.

9. ¿Qué es y qué permite hacer el CLR?

La Common Language Runtime simplifica el desarrollo de aplicaciones, provee un entorno de ejecución robusto y seguro, soporta varios lenguajes y simplifica el despliegue y la administración.
La CLR es un entorno administrado (managed), en el cual los servicios comunes, como garbage collection y seguridad, son provistos automáticamente.

10. ¿Qué es el MSIL?

El Microsoft intermediate language (MSIL) es un conjunto de instrucciones independiente de la CPU que se pueden convertir de forma eficaz en código nativo.

11. ¿Qué es el CTS?

El CTS (Common Type System) es un sistema común de tipos que define la forma en la que los tipos deben ser declarados, utilizados y administrados por el runtime.

12. ¿Qué es el CLS?

El CLS (Common Language Specification) es un conjunto de reglas y convenciones que todos los lenguajes compatibles con .NET deben seguir para garantizar que puedan interoperar entre sí.

13. ¿Dónde se encuentran las instancias de los objetos administrados por el GC?

Las instancias de los objetos administrados por el GC (Garbage Collector) se encuentran en una zona especial de la memoria llamada Heap administrado (Managed Heap).

14. ¿Cuáles son los dos métodos más notorios que deben implementar las clases para trabajar correctamente con la recolección de elementos no utilizados y matar las instancias administradas y no administradas?

Los métodos más notorios que deben implementar las clases son uno denominado FINALIZE y otro llamado DISPOSE.

15. ¿De dónde heredan las clases el método Finalize?

Este método se hereda de System.Object

16. ¿Cuál es la firma que implementa el método “Finalize”?

Se deberá declarar como "Protected" y "Override", no devuelve nada como retorno.

protected override void Finalize()

17. ¿Qué método se utiliza para que el GC recolecte los elementos no utilizados?

En .NET provee un método explícito para forzar la recolección, aunque su uso no es recomendado en la mayoría de los casos:

GC.Collect();

18. ¿Qué método se utiliza para suspender el subproceso actual hasta que el subproceso que se está procesando en la cola de finalizadores vacíe dicha cola?

Para suspender el subproceso actual hasta que el subproceso que está procesando la cola de finalizadores vacie dicha cola:

GC.WaitForPendingFinalizers();

19. ¿Cuándo se ejecuta el método collect del GC que método se ejecuta en los objetos afectados?

Cuando se ejecuta el método GC.Collet() se ejecuta el método finalizador del objeto identificado para su recolección.

20. ¿Qué método debería exponer una clase bien diseñada teniendo en consideración que no posee destructor?

Debe exponer el método Dispose()

Firma: public void Dispose()

21. ¿Cómo obtengo el método “Dispose”?

Implementando la iterfaz IDisposable.

22. ¿Qué se programa en el método “Dispose”?

Se liberan recursos administrados que implementan IDisposable (por ejemplo, streams, conexiones).
Y también se liberan recursos no administrados (archivos, sockets, handles, memoria nativa).

23. ¿Se pueden combinar el uso de “Dispose” y “Finalize”?

Si, El Dispose en general para liberar recursos NO administrados y el Finalize para los recursos administrados por el GC.

24. ¿A qué se denomina “Resurrección de Objetos”?

La resurrección de objetos ocurre cuando un objeto que estaba marcado para recolección por el GC vuelve a ser accesible porque su finalizador (Finalize) lo “revive” asignándolo a una variable estática o de alcance global.

25. ¿A qué se denomina “Generación” en el contexto de la recolección de elementos no utilizados?

En .NET, una generación (generation) es un grupo de objetos en el heap categorizados según su tiempo de vida estimado.

26. ¿Qué valores puede adoptar la “Generación” de un objeto?

Puede oscilar entre 0 y 2.

27. ¿Cómo se puede obtener el número de veces que se ha producido la recolección de elementos no utilizados para la generación de objetos especificada?

Para obtener el número de veces que el Garbage Collector (GC) ha recolectado objetos de una generación específica usando el método estático:

GC.CollectionCount(int generation)

28. ¿Cómo se obtiene el número de generación actual de un objeto?

Para obtener la generación actual de un objeto en el heap usando el método estático:

GC.GetGeneration(object obj)

29. ¿Cómo se puede recuperar el número de bytes que se considera que están asignados en la actualidad?

Para poder obtener el número aproximado de bytes actualmente asignados en el heap administrado usando el método estático:

GC.GetTotalMemory(bool forceFullCollection)

30. ¿Qué utiliza para convertir un objeto en “no” válido para la recolección de elementos no utilizados desde el principio de la rutina actual hasta el momento en que se llamó a este método?

Para evitar que el Garbage Collector (GC) considere un objeto como elegible para recolección temporalmente:

GC.KeepAlive(object obj)

31. ¿Cómo se solicita que el sistema no llame al finalizador del objeto especificado?

Para evitar que el Garbage Collector (GC) llame al finalizador (Finalize) de un objeto, se utiliza el método estático:

GC.SuppressFinalize(object obj)

32. ¿Cómo se solicita que el sistema llame al finalizador del objeto especificado, para el que previamente se ha llamado a “SuppressFinalize”?

Cuando ya se ha llamado a GC.SuppressFinalize(obj) y querés restaurar la ejecución del finalizador para ese objeto, se utiliza el método:

GC.ReRegisterForFinalize(object obj)

33. ¿Cómo se obtiene el número máximo de generaciones que el sistema admite en la actualidad?

Para obtener el número máximo de generaciones que el Garbage Collector admite usando el método estático:

GC.MaxGeneration
